## 개발 환경

### 1. README대로 서버를 띄우면 명령마다 오류
- **증상:** `npx prisma migrate dev`가 `P1001: Can't reach database server at localhost:5433`, `server/`에서 `docker compose up -d`가 `empty compose file`.
- **원인:**
  - Docker Desktop이 꺼져 있었다 (DB 컨테이너가 없음).
  - `server/docker-compose.yml`이 첫 커밋 때부터 **빈 파일**로 들어 있어서, `server/`에서 compose를 실행하면 루트 파일 대신 빈 파일을 읽었다.
  - Prisma 7은 설치·마이그레이션 때 클라이언트를 자동 생성하지 않는데 README에 `npx prisma generate`가 없었다.
- **해결:** 빈 파일 삭제, README에 "Docker 먼저 실행", 단계별 `cd`, `prisma generate` 추가, `server/.env.example` 추가 (`74f17f8`).

### 2. 사진 OCR이 "사진의 글자를 읽지 못했습니다"
- **증상:** 책 분석이 502. 서버 로그에는 Vision `403: Method doesn't allow unregistered callers`.
- **원인:** README에 넣은 `cp .env.example .env`가 **기존 `.env`를 덮어써** 키가 모두 빈 값이 됐다 (`GOOGLE_VISION_API_KEY`, `ANTHROPIC_API_KEY`, `JWT_SECRET`). `.env`는 커밋하지 않으므로 되살릴 수 없었다.
- **해결:** 사용자가 키를 다시 넣고 서버 재시작. README를 `cp -n`(이미 있으면 덮어쓰지 않음)으로 바꿈.
- **교훈:** 파일을 만드는 명령을 문서에 넣을 때는 이미 있는 경우를 먼저 생각한다. 배포 안내(`doc/deploy.md`)도 모두 `cp -n`으로 썼다.

### 3. 셸 스크립트 줄 끝
- **증상:** 커밋할 때 `scripts/adb-reverse.sh`에 "LF will be replaced by CRLF" 경고.
- **원인:** 이 저장소는 `core.autocrlf=true`라 다시 받으면 CRLF가 되고, bash는 줄 끝의 CR 때문에 스크립트를 실행하지 못한다.
- **해결:** `.gitattributes`에 `*.sh text eol=lf` (`e83778d`).

### 4. 메모리 부족으로 백그라운드 서버가 자동 종료
- **증상:** 확인용으로 띄운 서버(3100, 3002)가 작업 도중 사라짐. 브라우저 화면 캡처도 반복해서 시간 초과.
- **원인:** PC 메모리가 부족해지면 Claude Code가 쉬고 있는 백그라운드 작업을 정리한다 (코드 문제 아님). Docker·에뮬레이터·여러 프로젝트를 함께 띄운 상태였다.
- **대응:** 확인이 끝난 서버는 바로 끈다. 오래 걸리는 확인은 메모리를 덜 쓰는 방법(브라우저 대신 API 직접 호출)으로 한다.

### 5. 다른 프로젝트가 같은 3000번 포트 사용
- **증상:** `netstat`에 `[::1]:3000`을 다른 프로젝트(`pr-zombie-hunter`의 vite 개발 서버)가 잡고 있었다.
- **영향:** 휴대폰 요청은 IPv4(127.0.0.1)로 가서 우리 서버에 닿았지만, `localhost`가 IPv6로 풀리는 도구에서는 엉뚱한 서버로 갈 수 있다.
- **대응:** 두 프로젝트를 함께 띄울 때는 한쪽 포트를 바꾼다 (`PORT=3100 npm start` + `PORT=3100 bash scripts/run-android.sh`).

## 안드로이드 실기기

### 6. 앱에서 "서버에 연결할 수 없어요"
- **원인 1 — 포워딩 없음:** 같은 폰이 `adb devices`에 두 줄(`IP:포트`, `adb-...-tls-connect`)로 잡혀, README의 `adb reverse tcp:3000 tcp:3000`이 `more than one device`로 실패하고 있었다. 휴대폰의 `localhost:3000`이 아무 데도 이어지지 않음.
- **원인 2 — 평문 http 차단:** Android 9+(테스트 폰은 SDK 37)는 암호화되지 않은 `http`를 기본으로 막는다.
- **해결:** `-s`로 기기를 골라 포워딩, **디버그 빌드에서만** `usesCleartextTraffic="true"` (`android/app/src/debug/AndroidManifest.xml`, 배포 빌드는 그대로).

### 7. 화면은 뜨는데 마인드맵·관리·최근 스크랩이 계속 로딩 (무선)
- **원인:** 무선 디버깅이 끊겼다 다시 이어지면 **포트가 바뀌고 예전 포워딩이 사라진다** (46267 → 38001). 요청이 서버에 닿지 않는데, 앱은 모든 요청에 응답을 90초까지 기다리도록 돼 있어 로딩만 돌았다.
- **해결:**
  - 일반 요청 응답 대기 15초, 분석만 90초 → 15초 뒤 "다시 시도" 화면 (`c3200e4`).
  - `scripts/adb-reverse.sh`: 연결된 기기를 찾아 예전 포워딩을 지우고 다시 건 뒤, 휴대폰 안에서 서버 응답까지 확인 (`a4e0459`).
- **스크립트 첫 버전의 버그:** 같은 폰의 두 연결은 포워딩 목록을 같이 쓰는데, 두 번째 연결을 정리하면서 방금 건 포워딩까지 지웠다. 정리를 먼저 한 번에 하도록 순서를 바꿈.

### 8. USB로 바꾸니 다시 데이터를 못 불러옴 (11-04)
- **원인:** 포워딩은 **연결 하나에만** 걸린다. 무선에서 USB로 바꾸거나 케이블을 다시 꽂으면 새 연결에는 포워딩이 없다. 서버를 켜는 것과는 별개다.
- **해결:** `scripts/run-android.sh` — 포워딩을 먼저 걸고, USB를 우선해 기기를 고르고, 서버 주소(`--dart-define=API_BASE_URL`)를 넣어 `flutter run` (`b07acc3`).
  앱을 띄운 채 연결만 바뀌면 `bash scripts/adb-reverse.sh`만 다시 실행한다.

### 9. 데이터가 너무 적게 보임
- **원인:** 서버·DB·연결은 정상. `.env` 사고(2번) 뒤 새로 가입한 계정으로 로그인해 있었고, 기존 데이터는 다른 계정에 있었다.
- **상태:** 오해였음을 확인 (코드 수정 없음).

## 분석 품질

### 10. 학술 용어 대신 풀어 쓴 이름, 기존 태그만 다시 붙임
- **증상:** "불안과 지위 경쟁", "염세주의적 거리두기" 같은 이름. 원문에 "염세주의"가 직접 나오는데 빠지고, 이미 있는 태그만 다시 붙음. 뉴스(사법개혁 기사)에도 "상대적 박탈감"이 붙음.
- **원인:** 개념은 요약이 아니라 원문 전체에서 뽑는다. 문제는 지시문이었다.
  - 기존 태그를 "같은 개념이면 반드시 재사용"하라고 강하게 지시하면서, "원문에서 먼저 고르고 나중에 맞춰 본다"는 순서가 없었다 → 관련만 있어도 기존 태그가 최대 3개 자리를 차지.
  - 조합형("A와 B")·설명형 이름 금지, 원문 개념어 우선 규칙이 없었다.
  - 분석 모델(Haiku 4.5)의 학술 용어 정확도 한계.
- **해결 (`a10b0c2`):** 고르는 순서 명시, 원문 학술 용어 우선, 나쁜 예 → 바른 이름 짝, 채점 기준표 감점 추가. 분석 모델을 Sonnet 5.5로 (effort medium).
- **모델 비교 (같은 책 사진):** Haiku 4.5 새 개념 0개·10원 / Opus 5.5 2개·89원(비싸서 제외) / Sonnet 5.5 2개·29원(채택).
- **효과 (11-01 기록 기준 평균):** 책 3.4 → 4.4점, 기사 2.8 → 3.6점. 태그 이름 평균 8자 넘음 → 약 5자. 엉뚱한 기존 태그 재사용이 사라짐. 비용은 책 약 30원, 기사 약 45원.
- **남은 점:** 뉴스에서 핵심 쟁점보다 넓은 상위 개념으로 묶는 경향(개념 적합성 평균 3.2). 뉴스 샘플이 더 쌓인 뒤 판단.

### 11. 정치 기사에서 태그가 0개
- **증상:** 같은 기사(오세훈·정청래 기사)를 다섯 번 분석해 네 번 태그가 빈 목록. 태그가 0개면 태그 확인 화면에서 저장 버튼이 꺼져 스크랩을 저장할 수 없다.
- **원인:** 경선·세력 다툼 위주라 학술 개념과 연결이 약한 기사에서, 지시문의 "반드시 특정 학자·이론과 직접 연결", "억지로 채우지 말 것"이
  "최소 1개는 포함"보다 강하게 작용했다. 함께 바꾼 풀이 지시와는 무관함을 확인 (커밋해 둔 이전 지시문, 기존 태그 5개로도 0개).
- **해결:** 응답 스키마의 `tags`에 `minItems: 1`(API가 받아들임을 확인), 지시문의 태그 수를 "1~3개, 가장 가까운 개념을 최소 1개"로.
  다시 돌린 결과 태그 1~2개, 채점 3.2 → 4.4점.

### 12. 바꾼 뒤에도 결과가 예전 그대로
- **원인:** 3000번 서버를 재시작하지 않아 예전 모델·지시문이 계속 쓰였다 (두 번 반복). 분석 기록의 `models.analysis`로 확인할 수 있다.
- **해결:** 서버 코드(`claudeService.js` 등)를 바꾸면 서버를 재시작해야 한다. 기록에 모델이 남으므로 결과가 이상하면 먼저 모델부터 본다.

### 13. 채점 기준의 빈틈
- **맞는 학자 출처를 감점:** "권력분립 — 몽테스키외 『법의 정신』"을 "원문에 없는 학자"라며 감점. 분석 지시는 새 개념 설명(`description`)에 학문적 기원을 쓰라고 하는데, 채점은 모든 필드를 원문으로만 판단했다.
  → `reason`·`explanation`은 원문 기준, `description`의 출처는 널리 알려진 맞는 내용이면 감점하지 않게 나눔. 다시 채점해 보니 "출처는 학계 지식으로 맞다"로 바뀜.
- **추측성 재사용 감점:** 뉴스 4건 중 3건에서 "재사용하지 않은 판단은 맞다"고 쓰고 "도구화와 연결될 여지" 같은 추측으로 3점.
  → 같은 개념의 기존 태그가 없으면 5점, 감점하려면 놓친 태그가 원문의 어떤 개념과 같은지 짚게 함 (3 → 5점 확인).
- **태그가 없을 때 근거 5점:** 위반할 내용이 없다며 만점 → 태그가 없으면 이름·근거·근거 문장 항목은 null.
- 같은 때 풀이 지시도 보강: 원문의 사실을 짚어 개념과 잇되, 원문에 없는 배경을 이 글의 내용처럼 단정하지 않게 함.

## 앱·서버

### 14. 기사 분석에서 "서버 오류가 발생했습니다"
- **찾는 법:** 500 문구는 원인이 서버 콘솔에만 찍힌다. 사용자 계정으로 조회 요청 26건을 보내 봤더니 모두 정상이라
  바꾸는 동작으로 범위를 좁혔고, 휴대폰을 오류 기록용 서버(3100)로 돌려 재현해 로그를 받았다.
- **원인:** 기사 사이트가 404를 돌려주자 크롤러가 상태 코드 없는 `Error('페이지를 가져올 수 없습니다: 404')`를 던졌고,
  전역 에러 핸들러가 이를 500 "서버 오류"로 바꿨다. 어떤 주소였는지도 로그에 남지 않았다.
- **해결:** 크롤러 오류를 상태 코드와 안내 문구로 구분 — 없는 기사(404·410) 400, 사이트가 막음(401·403·429) 502,
  연결 실패·시간 초과(15초) 502. 실패한 주소를 로그에 남김. `test/crawlerService.test.js` 추가.

### 15. 가짜 클립보드가 실제 앱에 남아 있음 — 미해결
- **증상:** 14번에서 새로 남긴 로그의 주소가 `https://hani.co.kr/arti/society/1162` — 실제 기사가 아니다.

### 16. 마인드맵에서 개념을 누를 때마다 배치가 뒤섞임, 가끔 세로 한 줄

- **해결 (`b093c14`):** 직전 배치를 넘겨 새 가운데에서 본 예전 방향 순서대로 놓고, 직전 가운데는 눌러 들어온 반대쪽에 둠. 1단계가 1~2개면 좌우 배치.

### 17. 토큰 갱신 뒤 사진 업로드 재전송 실패 (④ 연동 중)

## 배포

### 19. Docker 빌드 실패 — 쓰지 않는 puppeteer
- **증상:** 배포용 이미지 빌드 중 `npm ci`가 `Failed to set up chrome ... Set "PUPPETEER_SKIP_DOWNLOAD"`로 실패.
- **원인:** 첫 커밋 때부터 서버 의존성에 puppeteer(크롬 자동화)가 들어 있었는데 코드 어디에서도 쓰지 않는다 (크롤러는 cheerio). 설치 때 크롬을 내려받으려다 실패.
- **해결:** 의존성에서 제거. 이미지가 수백 MB 작아지고 서버 테스트는 그대로 통과.
- **같이 확인한 것:** PC Docker로 배포 구성(DB + 서버)을 별도 이름으로 띄워 마이그레이션 적용, 회원가입·로그인·조회, 기록 폴더 쓰기, 백업 스크립트까지 확인.
  Caddy의 HTTPS 인증서 발급은 실제 도메인·EC2가 있어야 해 서버에서 처음 띄울 때 확인한다.

### 22. 배포 서버에서 비용·채점 기록이 안 남음 (11-05 발견)
- **증상:** 배포 서버 로그에 `[잔액] 기록 실패: EACCES: permission denied, open '/app/logs/credit.jsonl'`, `[기록] 실패: ... analysis-2026-11.jsonl`. 분석 자체는 성공.
- **원인:** compose에서 `./server/logs`를 직접 붙였는데, 서버에 그 폴더가 없어 Docker가 **root 소유**로 만들었다. 컨테이너는 `node` 사용자로 돌아 쓸 수 없었다.
- **해결:** 이름 있는 볼륨(`server_logs:/app/logs`)으로 바꿈. 이름 있는 볼륨은 이미지 안 `/app/logs`의 소유자(node)를 따른다.
  기록 보기는 `docker compose -f docker-compose.prod.yml exec server npm run eval:report`.
- **같이 고친 것:** Prisma가 OpenSSL 버전을 찾지 못한다는 경고 → 서버 이미지에 `openssl` 설치.

### 23. 배포용 앱에서 책 분석이 "요청을 처리하지 못했어요" — 조사 중 (11-05)
- **증상:** 어제(11-04) 18:46에 배포 서버로 책 분석 2건 성공. 앱은 그대로인데(배포용 APK, 11-04 18:18 설치) 오늘 분석하기를 누르면 "요청을 처리하지 못했어요".
- **확인한 것:**
  - 배포 서버 db·server·caddy 정상, HTTPS 인증서 정상.
  - PC에서 배포 서버로 같은 책 분석 요청 → `200 OK`, 결과 정상. 그 응답을 앱의 해석 코드(`bookFromJson`)에 넣어도 정상.
  - 휴대폰에서 도메인이 탄력적 IP로 풀리고 80번 연결 정상.
  - **오늘 휴대폰에서 누른 분석은 서버 로그에 흔적이 없다** → 요청이 서버까지 오지 않았거나, 로그를 남기지 않는 4xx로 거절됐다.
- **문제:** "요청을 처리하지 못했어요"는 앱이 실패를 분류하지 못했을 때의 문구라 상태 코드도 오류 종류도 알 수 없었다. Caddy도 요청을 기록하지 않았다.
- **진단용 수정 (원인과 별개로 앞으로를 위해):**
  - 앱: 분류하지 못한 실패에 상태 코드나 오류 종류를 덧붙인다 (`요청을 처리하지 못했어요 (HTTP 502)`, `(unknown)`, `(TypeError)`). 실제 오류와 스택을 기기 로그(logcat `flutter`)에 남긴다.
  - Caddy: 모든 요청을 한 줄씩 기록 (`log` 지시어). 요청이 서버에 닿았는지부터 보인다.
- **다음:** 휴대폰을 USB로 연결해 기기 로그와 서버·Caddy 로그를 함께 보며 재현.

## 작업 과정

### 20. 테스트가 실제 Claude API로 나가려 함
- **원인:** 분석이 대체 모델(`fallbacks`) 때문에 `client.beta.messages.stream`을 쓰게 됐는데, 테스트는 `client.messages.stream`만 가짜로 바꾸고 있었다 (키가 없는 테스트 환경이라 실제 호출은 일어나지 않고 인증 오류로 실패).
- **해결:** 테스트에서 두 경로를 모두 가짜로 바꿈.

### 21. 작업 중 실수
- **커밋에 다른 변경이 섞임:** 미리 스테이징된 파일 삭제가 다른 커밋에 들어갔다. 원격에 올리기 전이라 커밋을 되돌려 다시 나눔. 커밋 전 `git diff --cached --stat`으로 확인한다.
- **스크립트 시험 중 실제 release 빌드 실행 (11-04):** `run-android.sh`를 가짜 `flutter`로 시험하려고 PATH에 `C:/...` 경로를 넣었는데,
  Git Bash에서는 `C:` 뒤의 콜론 때문에 PATH가 잘못 나뉘어 진짜 `flutter run --release`가 실행됐다. 빌드 도중 멈추고 그 프로세스만 정리,
  휴대폰 앱은 다시 설치되지 않음. → Git Bash에서는 `cygpath -u`로 바꾼 `/c/...` 경로를 쓴다.
- **시험하며 포워딩을 바꿔 둠 (11-04):** `PORT=3100`으로 시험하는 동안 휴대폰 포워딩이 3100으로 바뀌었다. 바로 3000으로 되돌림.
  → 휴대폰 상태를 바꾸는 시험 뒤에는 원래대로 되돌렸는지 확인한다.
- **진단 방법 오류:** 휴대폰에서 `nc`로 요청을 보내 "응답이 없다"고 판단했는데, 입력이 끝나자마자 `nc`가 연결을 닫아 응답을 받기 전에 끝난 것이었다. 응답을 기다리도록(`(printf ...; sleep 2) | nc`) 바꿔 다시 확인했다.
